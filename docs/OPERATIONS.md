# Эксплуатация и восстановление

## Что сохраняется

SQLite — источник истины для пользователей, сессий, контента и реакций. В памяти находятся только шаблоны, ключ CSRF и счётчики ограничения частоты.

При штатной остановке SIGINT/SIGTERM сервер прекращает принимать новые запросы и даёт активным до 10 секунд на завершение. SQLite закрывается после остановки HTTP. Перезапуск не удаляет данные.

## Резервная копия

При WAL-режиме нельзя считать копирование одного открытого `forum.db` достаточной резервной копией: часть подтверждённых данных может находиться в `forum.db-wal`.

Для локальной базы используйте встроенный backup SQLite:

```sh
mkdir -p backups
sqlite3 forum.db ".backup 'backups/forum-backup.db'"
sqlite3 backups/forum-backup.db 'PRAGMA integrity_check;'
chmod 600 backups/forum-backup.db
```

Для восстановления остановите сервер, сохраните текущий комплект файлов отдельной копией и укажите проверенный backup через `DB_PATH`. Не подменяйте активную базу под работающим процессом. Проверяйте восстановление на отдельном экземпляре, не на единственной копии данных.

Docker-том хранится вне контейнера. `docker compose down` сохраняет его; вариант с `--volumes` удаляет данные, поэтому не используйте его для обычного перезапуска. Скрипт `container-smoke.sh` создаёт и удаляет только свой временный тестовый том.

## Ограничения и ответы

| Ситуация | Поведение |
| --- | --- |
| Пустой/слишком длинный текст, неверные категории | 400; при создании поста поля сохраняются для исправления |
| Нет действующей сессии | 401, ссылка на вход |
| CSRF/Origin не прошли проверку | 403; обновить форму |
| Не найден объект/маршрут | 404 |
| Неверный HTTP-метод | 405 и Allow |
| Занятый email/username | 409 |
| Тело формы больше 256 KiB | 413 |
| Не form-urlencoded | 415 |
| Слишком много попыток | 429 и Retry-After |
| База закрыта/запрос не выполнен | 500 без внутренних деталей в браузере |
| Одновременно заняты четыре bcrypt-слота | 503 и Retry-After 2 секунды |
| Не отвечает health-check базы | 503 |

Пределы: заголовки 16 KiB; чтение заголовков 5 секунд; чтение запроса 15 секунд; обработка динамического запроса 10 секунд; запись ответа 30 секунд; idle connection 60 секунд; ожидание писателя SQLite 5 секунд.

Авторизация: 30 попыток на IP за 10 минут. Записи: 120 запросов в минуту на пользователя, либо IP до авторизации. Лимитер содержит максимум 4096 ключей; при заполнении отказывает новым ключам до освобождения старых. Он намеренно сбрасывается после перезапуска. Это защита одного экземпляра, не распределённая анти-DDoS-система.

## Публикация за HTTPS

- Пропускайте наружу только reverse proxy с TLS.
- Установите `COOKIE_SECURE=true`; прямой HTTP с такими cookie не предназначен для входа.
- Сохраняйте исходный `Host`, иначе проверка Origin законно отвергнет форму.
- Приложение не доверяет пользовательским forwarding-заголовкам. Для реальных IP-лимитов за proxy настройте limiter на нём.
- Ограничьте доступ к файлу базы и резервным копиям. `db.Open` создаёт файл с `0600`.
- Размещайте SQLite на локальном диске/томе. WAL не предназначен для общего сетевого файла между несколькими машинами.
- Не запускайте несколько экземпляров сервера на общей базе: хотя SQLite защищает записи, разные ключи CSRF и независимые лимитеры сделают такое развёртывание неудобным.
- Регулярно обновляйте Go и три разрешённые зависимости с повторным запуском тестов.

## Диагностика

```sh
curl -i http://localhost:8080/healthz
sqlite3 forum.db 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
docker logs discuss-hub
```

Приложение пишет структурированные ошибки в stdout, без паролей и сырых токенов. Ошибка запуска (порт занят, повреждённая база, неверная настройка) завершает процесс с ненулевым кодом, а не оставляет ложное сообщение о рабочем сервере.

**database is locked:** проверьте другой процесс/долгую транзакцию. Приложение ждёт до 5 секунд, затем возвращает ошибку. После снятия блокировки следующий запрос может продолжить работу; частично созданный пост не сохраняется.

**CGO disabled / C compiler missing:** для `mattn/go-sqlite3` нужен C-компилятор. Используйте поставляемый Dockerfile либо установите штатные developer tools вашей ОС.

**Docker daemon unavailable:** команда `docker` сама по себе не является движком. Запустите Docker Engine/Desktop с разрешения владельца управляемого компьютера или используйте CI на Linux. Успешный локальный `go test` не доказывает успешный Docker build.
