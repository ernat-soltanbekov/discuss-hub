Это показатели операторов, а не доказательство отсутствия всех ошибок. `cmd/server` проверен отдельным запуском процесса, поэтому его покрытие в обычном пакетном отчёте остаётся 0%.

Нагрузка включает 32 параллельных писателя (256 комментариев + 256 смен реакций), 16 HTTP-клиентов (160 записей + 160 чтений dashboard), 12 одновременных входов и 8 конкурирующих регистраций. Отдельно воспроизведены блокировка базы, отказ соединения, повреждённый файл, неизвестная версия схемы и враждебные формы.

Benchmark sentiment: **38 267 ns/op**, **72 320 B/op**, **8 allocs/op** для строки примерно 6 KB. Это локальный микробенчмарк алгоритма, не обещание времени ответа всей системы.

## Уточнение результата проверки зависимостей

В модуле `golang.org/x/crypto@v0.57.0` отмечен [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) для `openpgp`. Проект импортирует только `bcrypt`; `openpgp` отсутствует в его графе импортируемых пакетов. `govulncheck` не нашёл затронутых вызываемых символов или импортируемых пакетов. Сканирование Go не заменяет отдельную проверку системных компонентов контейнера и всех уязвимостей встроенного C-кода SQLite.

## Что пока не подтверждено

**Docker build/run в локальной среде:** на этом учебном компьютере Docker CLI установлен, но движок не стал доступен. До запуска Desktop сокет отсутствовал; после попытки запуска API отвечал HTTP 500, статус оставался `starting`. Поэтому успешная сборка и работа контейнера **не заявляются**. Проверены Dockerfile, наличие pinned base images, Compose-конфигурация и синтаксис smoke-script. Для закрытия пункта нужен работающий Docker: `sh scripts/container-smoke.sh` или CI job `container`.

**GitHub / CI:** репозиторий — [ernat-soltanbekov/discuss-hub](https://github.com/ernat-soltanbekov/discuss-hub). Этот отчёт фиксирует локальные проверки до публикации. Результат удалённой проверки конкретного коммита смотрите в [GitHub Actions](https://github.com/ernat-soltanbekov/discuss-hub/actions): workflow выполняет отдельные задания Go и Docker. Локальные результаты не подменяют статус этих заданий.

Живое объяснение проекта, предусмотренное аудитом, должен выполнить владелец проекта. Для подготовки предусмотрены архитектурная схема, разбор запроса, SQL и вопросы в [ARCHITECTURE.md](ARCHITECTURE.md).
