# discuss-hub

**Форум о внимательной инженерии, ежедневной практике и совместном росте.**

Проект Tomorrow School / 01-Edu: Go `net/http`, SQLite, серверные HTML-шаблоны и обычный CSS. Без фронтенд-фреймворков, JavaScript, ML-моделей и внешних AI-сервисов.

Автор проекта: **Yernat “GhostOfAstana” Soltanbekov** — студент Tomorrow School, с техническим образованием и военным прошлым; практикует боевые искусства по утрам с 2008 года. Проект отражает стремление присоединиться к команде Astana Hub и работать на пользу технологическому сообществу Казахстана. Это личный учебный проект, не официальный продукт названных организаций.

Вид интерфейса: [обсуждения](docs/images/home.jpg) · [аналитика](docs/images/insights.jpg).

## Быстрый запуск

Нужны **Go 1.26+**, C-компилятор (GCC/Clang) и включённый CGO: драйвер SQLite компилирует SQLite из исходников. При первом запуске Go скачает три разрешённые зависимости из `go.mod`.

```sh
git clone https://github.com/ernat-soltanbekov/discuss-hub.git
cd discuss-hub
go run ./cmd/server
```

Откройте [http://localhost:8080](http://localhost:8080). Нажмите **Join the hub**, зарегистрируйтесь и войдите. Регистрация не создаёт скрытую сессию: после неё показана форма входа.

`forum.db` и служебные файлы WAL создаются автоматически. В Git они исключены: реальные аккаунты, хеши паролей и сессии не должны попадать в репозиторий. Чтобы получить структуру сдачи вместе с пустой базой, выполните:

```sh
go run ./cmd/server -init-only
```

Собрать самостоятельный бинарник:

```sh
go build -trimpath -o bin/discuss-hub ./cmd/server
./bin/discuss-hub
```

Шаблоны, стили и SQL-схема встроены в бинарник через `go:embed`. Копировать их рядом с программой не требуется. После изменения исходных шаблонов нужно пересобрать/перезапустить программу.

## Запуск в Docker

Нужен работающий Docker Engine или Docker Desktop.

```sh
docker compose up --build
```

Адрес: [http://localhost:8080](http://localhost:8080). Compose сохраняет базу в именованном томе `forum-data` и открывает порт только на localhost.

Для проверки вручную, как в аудите:

```sh
docker image build -t discuss-hub .
docker images discuss-hub
docker run -d --name discuss-hub -p 127.0.0.1:8080:8080 \
  -v discuss-hub-data:/app/data discuss-hub
docker ps -a --filter name=discuss-hub
curl --fail http://localhost:8080/healthz
docker logs discuss-hub
# Остановить/запустить с сохранением данных:
docker stop discuss-hub
docker start discuss-hub
```

В образе нет Go-компилятора и исходников приложения. Базовые образы зафиксированы по digest для воспроизводимости. Процесс работает от UID/GID `10001`, не от root. `compose.yaml` дополнительно отключает Linux capabilities и делает файловую систему образа доступной только для чтения; том базы остаётся доступен для записи.

## Возможности

- Публичное чтение обсуждений, комментариев и счётчиков реакций.
- Регистрация с уникальными email и username; проверки выполняются и в приложении, и ограничениями SQLite.
- Пароли хешируются **bcrypt**. ID пользователей — **UUID v4**.
- Одна активная сессия на аккаунт, срок **24 часа**. Новый вход отзывает предыдущую сессию; выход из старого браузера не отзывает новую.
- Авторизованные участники создают обсуждения и ответы, ставят лайк или дизлайк. Повторная одинаковая реакция не дублируется; противоположная заменяет её. Есть отдельное удаление реакции.
- У обсуждения от одной до пяти категорий: Engineering, Tomorrow School, Martial Arts, Service & Leadership, Astana Tech.
- Фильтры по категории, собственным и понравившимся обсуждениям. Категорию можно сочетать с личным фильтром.
- Пагинация по 20 обсуждений/комментариев; все посты доступны и в списке sentiment.
- Адаптивный интерфейс, клавиатурная навигация, подписи полей, видимый фокус, страницы ошибок.
- `/insights`: настроение, самая активная категория и участник, пять постов по сумме лайков и дизлайков, sentiment каждого поста.
- `/insights/trending`: десять частых слов за последние 24 часа. Дополнительно доступен JSON: `/insights/trending?format=json`.
- `/about`: история и ценности автора проекта.

## Как считается аналитика

**Sentiment анализирует только содержимое поста**, не заголовок или комментарии. Регистр и пунктуация нормализуются. Считаются все вхождения целых слов: `good good` — два совпадения; `goodness` — ни одного.

| Положительные слова | Отрицательные слова |
| --- | --- |
| great, love, excellent, amazing, helpful, good, thanks, awesome | bad, hate, terrible, awful, horrible, wrong, broken, useless |

```text
score = positive_matches - negative_matches
score > 0 → Positive
score < 0 → Negative
score = 0 → Neutral
```

`great love bad hate` даёт `2 − 2 = 0`, то есть **Neutral**. `not good` даёт **Positive**: этот простой алгоритм не понимает отрицание, сарказм, контекст и другие языки. В интерфейсе рядом с результатом доступно объяснение формулы.

- Активность категории — SQL `COUNT` связей постов с категорией. Пост с двумя категориями учитывается по одному разу в каждой.
- Активность участника — количество его постов **плюс** комментариев, независимо от реакций.
- Top 5 — сумма положительных **и** отрицательных реакций на пост. Реакции на комментарии не входят.
- При одинаковой активности категории/пользователи сортируются по имени; посты с равной суммой реакций — от новых к старым.
- Настроение учитывает все посты. Для пустого форума три доли равны нулю. Округлённые доли могут дать 99,9% или 100,1%.
- Dashboard читается в одной транзакции: все показатели относятся к согласованному снимку SQLite. Агрегаты считаются SQL-запросами; тексты для словарного анализа обрабатываются последовательно.
- Trending использует **заголовок и содержимое**, диапазон `[сейчас − 24 часа, сейчас]`, частоту каждого слова и английские stop words. Будущие записи исключены, граница ровно 24 часа включена. При равной частоте слова сортируются по алфавиту.

## Демонстрационные данные

Демонстрационный режим добровольный и работает только с пустой базой:

```sh
DB_PATH=data/demo.db go run ./cmd/server -demo
```

Добавляются 6 примерных обсуждений, 3 аккаунта `demo_*`, комментарии и реакции. Все тексты обозначены как примеры. Пароли демоаккаунтов случайные и не сохраняются: известных тестовых паролей/администраторских входов в приложении нет. Для участия зарегистрируйте свой аккаунт.

Повторный `-demo` на непустой базе завершится ошибкой и не изменит её. Для повторного просмотра существующей демобазы запустите без флага:

```sh
DB_PATH=data/demo.db go run ./cmd/server
```

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ADDR` | `:8080` | Адрес и порт HTTP-сервера; для доступа только с этого компьютера используйте `127.0.0.1:8080` |
| `DB_PATH` | `forum.db` | Файл SQLite; каталог создаётся при необходимости |
| `COOKIE_SECURE` | `false` | `true` при HTTPS: Secure cookies, префикс `__Host-`, HSTS |

Для публикации в интернете используйте HTTPS reverse proxy, сохраняющий публичный `Host`, и `COOKIE_SECURE=true`. Приложение намеренно не доверяет `X-Forwarded-For` / `X-Forwarded-Proto`. Поэтому лимиты по IP за прокси относятся к IP прокси. На публичном reverse proxy настройте собственные ограничения запросов и размера тела. Подробнее: [эксплуатация](docs/OPERATIONS.md).

## Проверки

```sh
go test ./...
go test -race -count=1 ./...
go vet ./...
# Проверка случайными строками и Unicode:
go test ./internal/insights -run '^$' -fuzz FuzzSentimentInvariant -fuzztime 10s -parallel 2
# Микробенчмарк словарного анализа:
go test ./internal/insights -run '^$' -bench BenchmarkSentiment -benchmem
# Реальный HTTP-сервер, остановка и сохранение данных (нужен Python 3):
python3 scripts/live-smoke.py
# Реальная сборка/запуск/перезапуск контейнера в изолированном тестовом томе:
sh scripts/container-smoke.sh
```

Проверки покрывают регистрацию, изоляцию и отзыв сессий, уникальность при одновременной регистрации, запреты гостям, XSS/SQL injection/CSRF, лимиты тела запроса и числа попыток, все виды реакций, фильтры, SQL-статистику, границы 24 часов, пагинацию, параллельные чтения/записи, блокировку и повторное открытие базы, повреждённую/неподдерживаемую базу, HTTP 400/401/403/404/405/409/413/415/429/500/503.

Для каждого теста используется собственный временный файл SQLite. Тесты не трогают рабочую `forum.db`. Исключительно в тестах bcrypt использует меньшую стоимость для быстрого выполнения; сервер использует `bcrypt.DefaultCost` (10).

CI в `.github/workflows/ci.yml` повторяет сборку, форматирование, `go vet`, тесты с детектором гонок и контейнерный smoke-test. Факт наличия workflow сам по себе не означает, что удалённый прогон уже выполнен; фактические проверки записаны в [VALIDATION.md](docs/VALIDATION.md).
